# Replay — projections of real build runs

Spec for epic #202, ticket #203 · architecture §Data model (Replay artifact) + §Recorder contract.

A **replay artifact** (`<slug>.json`) is a generated **projection of a committed real agent run**:
the ordered build ops a driver plays to re-assemble a Shape Up breadboard at the run's own pacing.

**It is not a trace, and it is not a recording.** The recording is the trace pair in `traces/`,
committed beside it under the standard honesty labels and named in the artifact's `source`. If the
two ever disagree, the trace is the truth and the artifact is regenerated from it — never the other
way round. A reader who wants to know what actually happened should read `traces/<slug>.jsonl`; the
artifact is a convenience for a player, not a second account of the run.

Nothing here is played by a live model. The run happened once, at build time; a view-time driver
replays a committed file (hard constraint).

**Honesty rules (hard, the same ones `traces/README.md` states):**

- A board file and its trace pair are only ever produced by `portal/record-build.mjs` from a
  **real** Agent SDK run. **Never hand-write or hand-edit a board, a trace, or an op** — not one.
  If a run reads badly, the honest fix is a better run: tighten the prompt in
  `portal/record-build.mjs` and re-run with `--force`.
- `<slug>.json` is **generated** by `agent-layer/gen-replay.mjs` and drift-checked in CI
  (`tooling/drift-check.mjs`). Editing it by hand turns the gate red, which is the intended
  outcome, not an obstacle to work around.
- The artifact's `label` is exactly `Projection of the real run <slug>`. That wording is
  load-bearing: it is the artifact saying what it is, in the artifact itself.
- `briefs/<slug>.md` is the run's **human-authored input** — a person writing the problem
  statement is not the honesty contract's subject, and the brief states the problem, never the
  answer. It contains no board, no place list and no worked example, so nothing the agent produced
  was fed to it first.

## Files

```
replay/
  README.md              this contract
  briefs/<slug>.md       the brief handed to the run — human-authored INPUT
  <slug>.board.json      the board the run's ops actually built — the run's real OUTPUT
  <slug>.json            GENERATED: the ops, projected from the curated trace (drift-checked)
```

All three are committed (deploy = commit the artifacts). `--dry` output is a smoke test written to
a scratch dir and never lands here.

## Artifact shape

```json
{ "$description": "GENERATED by agent-layer/gen-replay.mjs — do not edit. …",
  "version": 1,
  "slug": "build-fieldwork-dispatch",
  "label": "Projection of the real run build-fieldwork-dispatch",
  "source": {
    "curatedTrace": "/traces/build-fieldwork-dispatch.jsonl",
    "rawTrace": "/traces/build-fieldwork-dispatch.raw.jsonl",
    "board": "/replay/build-fieldwork-dispatch.board.json",
    "brief": "/replay/briefs/build-fieldwork-dispatch.md",
    "sessionId": "…", "model": "claude-sonnet-5", "startedAt": "…Z", "durationMs": 131043 },
  "ops": [
    { "op": "place.add", "atMs": 45981, "phase": "implement",
      "params": { "label": "Today Overview" }, "fromStep": 9 }
  ] }
```

Every `source` value is copied from the curated `meta` — none of it is computed or authored here.

- `op` — one of the eight verbs in **`system/board-ops.mjs`**, which is the vocabulary's definition
  and the pure applier a driver replays with. An op that creates something carries only its label
  (and, for an affordance, its place): **an op never carries an id for the thing it creates**, so
  the ids are re-derived on replay rather than copied out of the trace.
- `atMs` — milliseconds from the run's `startedAt` to that step's `ts`. **Real pacing**, not an
  index: the gaps are how long the model actually took.
- `phase` — the step's PIV phase, verbatim from the trace.
- `fromStep` — the `seq` of the trace step this op came from. Every op resolves to one; open
  `traces/<slug>.jsonl` and find it.

Ops come from **successful op calls in any phase** — each op records the phase it ran in, and that
is not always `implement`: the recorder's own system prompt tells the agent to fix the board with
further ops inside the validate phase if the validate command fails, so a run that self-corrects
late projects validate-phase ops. A `--validate` invocation is not an op (it changes no state), and
a failed or fence-denied call is not an op (it changed nothing) — both stay visible in the trace,
which is where the governance story belongs.

## What the generator refuses

`agent-layer/gen-replay.mjs` emits nothing unless all of these hold:

- the trace pair passes `tooling/validate-trace.mjs` (four PIV phases in order, no null phase, the
  curated trace deriving from its committed raw sibling);
- every op call parses through the one shared grammar (`parseOpCommand`) — the same parser the
  recorder's fence denies with, so an unreadable command was never allowed into the run;
- every op call ran **`tooling/board-op.mjs` itself**, resolved and compared as a path identity —
  a filename suffix is not an identity, and an op is only an op if the build tool applied it;
- every op resolves to a `fromStep` present in the trace, in strictly increasing `seq` order;
- the trace projects to at least one op;
- **the reproduce check**: applying the projected ops from an empty board rebuilds
  `<slug>.board.json` exactly. If it does not, the board and the trace disagree and neither gets
  patched — the run is recorded again.
- **two-directional discovery**: a `<slug>.json` with no `<slug>.board.json` behind it is an error,
  not a file to ignore.

A build run's trace carries **0 artifacts**, and that is by design: the recorder denies `Write`
outright, so the board is built only through op calls and the Trace format's Write→artifact pairing
never fires. The board↔trace link is enforced by the reproduce check above instead.

## Workflow

```bash
node portal/record-build.mjs --slug <slug> --dry     # smoke test → scratch dir, never replay/
node portal/record-build.mjs --slug <slug>           # the real run → traces/ pair + <slug>.board.json
node agent-layer/gen-replay.mjs                      # project → replay/<slug>.json
node agent-layer/gen-replay.mjs --check              # what CI runs (via tooling/drift-check.mjs)
```

A re-run needs `--force`, which clears the stale board **and** the stale artifact first — a
projection of a run that no longer exists must never survive the run that replaced it.
