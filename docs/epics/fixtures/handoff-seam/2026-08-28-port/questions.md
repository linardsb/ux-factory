## The three that cost most, and the one sentence that would have removed each

1. **Q1, no iOS contract layer.** Every token in the spec had to be hand-mapped from `--color-x` to `neutralSemantic…ColorX`, and the mapping is a guess the web team never confirmed. The sentence: "On iOS, each `--color-x` / `--spacing-x` / `--radius-x` / `--type-x` token is `FactoryTokens.neutral<Group>…<X>`; the `neutral` semantic leaves are the contract, and the CSS `contract` group has no separate iOS build."

2. **Q9 to Q11, the sizes that are not tokens.** The 20px circle, 2px ring, 1px hairline and 44px minimum height are literals in the web component and the prose, so a tokens-only build has to fake them from spacing arithmetic. The sentence: "The row's non-token measurements are: check circle 20px, ring 2px, hairline borders 1px, minimum row height 44px, chip tracking 0.08em, and they ship as tokens `--size-check-circle`, `--stroke-ring`, `--stroke-hairline`, `--tap-target-min`, `--tracking-eyebrow`."

3. **Q16 and Q14, the field name and ownership of the row's data.** The web component uses `action` where spec and contract say `type`, and it owns `checked` while the spec calls it a prop; both had to be adjudicated without the web team. The sentence: "The care verb field is `type` everywhere (the web component's `action` is a stale alias), and `checked` is owned by the list, not the row: the row only reports toggles."
