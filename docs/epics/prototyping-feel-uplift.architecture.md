# Architecture — Prototyping-Feel Uplift

**PRD:** [prototyping-feel-uplift.prd.md](./prototyping-feel-uplift.prd.md) · **Created:** 2026-07-30

## Approach in one paragraph

Adopt the 2026 native web platform as the interaction engine and hand-write every pattern as a
`system/*.mjs` canon module — vendor nothing. The research pass (below) confirmed the big
prototyping tools are wrong-license or wrong-stack for this repo, while their signature
affordances (inspect bubbles, command palette, scrub values, before/after sliders, state morphs)
each cost tens-to-hundreds of lines of vanilla JS on top of Popover API + anchor positioning +
`@starting-style` + `linear()` springs + `@property` + same-document View Transitions. New
primitives follow the existing conventions exactly: generated data files with drift checks,
one-shot success-path analytics, token-only CSS, reduced-motion off-ramps, VR-gate discipline.

## Research

Background research (2026-07-30 session) verdicts, kept here so tickets don't re-litigate:

- **Skip as dependencies:** tldraw (source-available, paid commercial), Excalidraw (React),
  CodeMirror 6 (no clean no-build story, 90–120 KB), Sandpack/WebContainers (React / paid
  commercial / anti-static), ninja-keys (Lit runtime), interact.js (API surface ≫ need).
- **Steal as patterns (hand-write):** command palette (~150 lines over `<dialog>`/popover),
  before/after slider (~40 lines, `clip-path` + pointer drag), drag-to-scrub numerics (~20 lines
  pointer delta), pan/zoom (~1–2 KB, CSS transform + pointer + wheel), split/resizable panes
  (percentage flex-basis + drag clamp).
- **Use natively:** `linear()` spring easing (Safari 17.2+/Chrome 113+/Firefox 112+ — the single
  cheapest tool-feel win), Popover API, `@starting-style` + `allow-discrete`, CSS anchor
  positioning (Chrome 125/Safari 26/Firefox 147 — needs legible un-anchored fallback), same-doc
  View Transitions (Chrome 111/Safari 18/Firefox 144), `@property`, container queries, `:has()`,
  relative color syntax, `light-dark()`.

## Browser-support policy (decided)

**Baseline + progressive extras.** Load-bearing behaviour uses only cross-engine features.
The three recent-but-cross-engine features (anchor positioning, same-doc View Transitions,
scroll-driven animations) ship with working fallbacks (static position / instant swap / IO-based
reveal). The ~7 Chrome-only items (`interpolate-size`/`calc-size()`, `field-sizing`,
`appearance: base-select`, invoker commands, `sibling-index()/count()`, `::scroll-marker/button`)
may appear only as cosmetic enhancement where the fallback is complete. Cross-document View
Transitions are out (no Firefox support at all).

## Copy: dual register

Every section a wave touches: first line = 1–2 plain sentences (what it is, why a hiring manager
cares), precise term kept immediately alongside (bold or in the glossary style), depth pushed into
disclosures. Rewrites run through `/no-ai-slop` + `/humanizer` before commit. `glossary.mjs`
coverage extends to any term that survives in the first layer.

## Constraints that shape implementation (from repo memory — do not rediscover)

- **VR gate:** captures under NO-preference motion; zero-churn comes from `animations:'disabled'`
  + rest==final. Any at-rest change (copy, chrome hint, new visible controls) regenerates its
  baselines in the same PR (`update:docker`, clean worktree under /Users). New JS-gated at-rest
  controls behind `matchMedia('reduce')` alone WILL churn. `waitVisible` handles for
  IntersectionObserver-gated reveals; re-measure loop already fixed (#138).
- **`body{overflow-x:clip}`** makes `position:sticky` a no-op site-wide — panels/rails are
  structural layouts, never sticky.
- **Analytics:** synthetic paths are the entire payload — static literals, one-shot, success-path
  only; never fire from a slot or settled-state flag (spine memory note).
- **Pack skin on protos (Wave 4 decision):** `pack-boot.js` is hard-allowlisted to the six IA
  pages and VR relies on its guaranteed no-op default. Extending to proto pages means editing the
  allowlist AND `PACK_RE` AND the dock's `PACKS` mount, and accepts churn on the two proto
  baselines; the ticket must prove the no-op default still holds on every page.
- **Token changes** regenerate contract CSS + handoff pack together (memory: stale pack fails
  `verify`).
- **Honesty contract:** inspect data is generated from real sources; the parameter count is
  measured; nothing presented as tooling output is hand-written.

## Risks / spikes

- **View Transitions × VR:** `startViewTransition` wraps DOM mutations the gate screenshots
  mid-run? The gate disables animations, but the wrapper must not change final frames. Spike:
  one morph on /build behind the reduced-motion off-ramp, run the VR gate before rolling out
  "everywhere feasible".
- **Anchor-positioning fallback legibility:** verify the un-anchored bubble is usable on
  Firefox ≤146 before inspect mode ships site-wide.
- **Inspect on shadow-DOM wc/ components (Wave 4):** `getComputedStyle` and `data-inspect`
  instrumentation cross the shadow boundary differently; spike on one vd- wrapper first.
