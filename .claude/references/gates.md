# The gate stack — what each gate owns, and what it states it cannot reach

Load this when adding a gate, changing one, or working out why a green run proves less than it looks like it does. Per-module invariants are NOT here — they live in each module's own file header, which is what an editor sees. This file holds only what no single file owns: which gate covers what, and where each one's coverage stops.

**The convention that makes the stack readable:** every gate STATES the boundary it cannot reach, and names the gate that owns the other side. Groups 9, 11, 13, 16, 18, 19, 23, 24, 25, 26, 27 and 28 each carry that sentence, and so do the journey drivers. A gate that claims total coverage is the one to distrust — see [[the check that cannot fail]]: every #137 defect survived a green gate the same way, by skipping the thing it tested. Mutate the source; run the function, don't grep it.

**What runs in CI (`verify` job):** `build-checks.mjs`, the generator drift checks, token-lint, and the visual-regression gate. **Everything else is operator-run** — the journey drivers, `vt-verify`, `vt-stack-audit` — and is not a merge blocker.

## The pixel gate — `tooling/visual-regression/`

Isolated Playwright (the other dependency-carrying tool). CI visual-regression gate: screenshots the 11 shipped pages (6 IA + /roundtrip + /build + /components + 2 proto) under neutral + saulera packs, pixel-diffs vs committed Linux baselines.

**Capture = measure → resize → wait for any `activateOn:'visible'` beat → RE-measure until the height stops moving.** Skip that last step and the shot silently truncates whatever the beat added (#9 gate 3/3; /build + the re-measure fix #138).

**What it cannot see** — the reason the journey drivers exist:
- It never INTERACTS, so a dead control compares clean.
- It MASKS iframe content, so a 404 inside a device frame passes forever (group 24 owns that).
- `update:docker` regenerates the baseline **from the same tree**, so it re-baselines a regression and the next gated run passes. This is why `vt-stack-audit` exists.
- Its `reducedMotion:'reduce'` is a no-op — it captures under NO-PREFERENCE.
- `maxDiffPixels:100` swallows a few changed digits; a green update run is not proof a page didn't change.

**Baseline discipline:** any at-rest layout or copy change to a shipped page invalidates its baseline — regenerate via `cd tooling/visual-regression && npm run update:docker` **in the same PR**. Local gates don't render pages so they can't catch it, and a same-height sentence reorder still churns ~38k pixels, so never decide a regen by height. Run it from a clean detached worktree under `/Users` (not `/private/tmp` — Docker sharing), because it screenshots the DIRTY tree.

## The morph gates — `vt-verify.mjs` and `vt-stack-audit.mjs`

**`vt-verify.mjs`** — /build's THIRD driver, and the one the other two structurally cannot be: it asserts that the view-transition morphs actually OPEN. `build-checks` and `build-journey` only ever assert END STATES, and `system/morph.mjs` falls through to a plain mutation whenever it cannot transition — so a morph that silently stopped firing leaves every other assertion green. It wraps `document.startViewTransition` before any module evaluates and reads `document.getAnimations()` for the running `::view-transition-*` pseudos, per engine: /build's boot opens ZERO transitions (the property the pixel gate depends on — the gate never interacts, so at-rest capture can never race a morph), each of the three families opens exactly one with the group names we wrote (`bx-q-<act>` · `bb-place-<id>` · `bx-pattern` — a duplicate name would abort the whole transition silently, and shows up here as a MISSING group), a rename opens none, and reduced motion opens none while the interaction still completes. #172 extended it past /build to the five other wrapped surfaces (home + instance wizard steps, the study's tab and remove verbs, a trace step), which name nothing and so assert the count and the end state rather than group names. **Load is an EXPECTED COUNT there, not an assumed zero:** home opens TWO at load and they are not a morph wrapper's — `spine.mjs:147,149` runs the hero re-skin and its revert through its own `crossfade()` (#72). #213 extended the factory block to sample AFTER the interactions that postdate it — the #209/#240 take-over handover and #210's keep-rail copy + export clicks, movement proven first (took over · `?b=` in the bar · a download event) — because zero at rest says nothing about a chain that runs afterwards.

**`vt-stack-audit.mjs`** — the check to run BEFORE naming anything for a view transition, and the one #172 needs on every page it touches — **but NOT YET as an unattended gate:** hazard A false-positives on `/index` and `/roundtrip` (2 of the 7 shipped IA pages; hazard B is clean on all seven), because the noise filter discounts elements the engine reports as ANIMATING but not elements with no box at all at sample time. **Fix #190 before #172 adopts it, or the red gets ignored.**

`view-transition-name` is inert in what an element PAINTS, not in how it STACKS: naming it makes it a stacking context AND a containing block for abs/fixed descendants. #171 shipped a real at-rest regression through exactly that — naming the breadboard places promoted them into the same paint step as the absolutely positioned SVG drawing the connection lines, which comes EARLIER in source order, so every line was covered and clipped. **The pixel gate cannot catch this class of bug** (see its `update:docker` note above).

Two hazards per page: **A** · does anything MOVE when every name is removed (containing-block shift; elements with running animations are discounted by asking the engine, not by re-sampling). **B** · does any positioned element overlap a named one from OUTSIDE its subtree with `z-index: auto` (the #171 bug). /build carries a state matrix because its named elements only meet the line overlay in states the gate never captures — connect mode, a derived pack, an emptied board.

## What no gate can see

Stated so it is not rediscovered as a bug:

- **A deleted mount can orphan its CSS.** A re-scoped transition block is dead if the deleted module armed its class; nothing here detects it (PR #261).
- **A guard's WIRING**, as opposed to its predicate — groups 9 and 11 both live with this.
- **The screen-reader pass** and the judgement-level a11y items (labels that say what they do, empty state as invitation, colour never the only signal). Axe and Lighthouse are absent; axe belongs in the VR tool light and dark, Lighthouse stays operator-run because it is machine-dependent theatre.
- **Whether a green gate tested anything at all.** The recurring defect shape in this repo: the check skipped the thing it tested. Mutate the source; run the function, don't grep it.
