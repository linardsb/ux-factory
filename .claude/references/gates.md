# The gate stack — what each gate owns, and what it states it cannot reach

Load this when adding a gate, changing one, or working out why a green run proves less than it looks like it does. Per-module invariants are NOT here — they live in each module's own file header, which is what an editor sees. This file holds only what no single file owns: which gate covers what, and where each one's coverage stops.

**The convention that makes the stack readable:** every gate STATES the boundary it cannot reach, and names the gate that owns the other side. Groups 9, 11, 13, 16, 18, 19, 23, 24, 25, 26, 27, 28 and 34 each carry that sentence, and so do the journey drivers. A gate that claims total coverage is the one to distrust — see [[the check that cannot fail]]: every #137 defect survived a green gate the same way, by skipping the thing it tested. Mutate the source; run the function, don't grep it.

**What runs in CI (`verify` job):** `build-checks.mjs`, the generator drift checks, token-lint, and the visual-regression gate. **Everything else is operator-run** — the journey drivers, `vt-verify`, `vt-stack-audit` — and is not a merge blocker.

## The pixel gate — `tooling/visual-regression/`

Isolated Playwright (the other dependency-carrying tool). CI visual-regression gate: screenshots the 11 shipped pages (6 IA + /roundtrip + /build + /components + 2 proto) under neutral + saulera packs, pixel-diffs vs committed Linux baselines.

**Capture = measure → resize → wait for any `activateOn:'visible'` beat → RE-measure until the height stops moving.** Skip that last step and the shot silently truncates whatever the beat added (#9 gate 3/3; /build + the re-measure fix #138).

**What it cannot see** — the reason the journey drivers exist:
- It never INTERACTS, so a dead control compares clean.
- It MASKS iframe content, so a 404 inside a device frame passes forever (group 24 owns that).
- `update:docker` regenerates the baseline **from the same tree**, so it re-baselines a regression and the next gated run passes. This is why `vt-stack-audit` exists.
- Its `reducedMotion:'reduce'` is a no-op — it captures under NO-PREFERENCE.
- `maxDiffPixels:100` swallows a few changed digits; a green update run is not proof a page didn't change.

**Baseline discipline:** any at-rest layout or copy change to a shipped page invalidates its baseline — regenerate via `cd tooling/visual-regression && npm run update:docker` **in the same PR**. Local gates don't render pages so they can't catch it, and a same-height sentence reorder still churns ~38k pixels, so never decide a regen by height. Run it from a clean detached worktree under `/Users` (not `/private/tmp` — Docker sharing), because it screenshots the DIRTY tree.

## What no gate can see

Stated so it is not rediscovered as a bug:

- **A deleted mount can orphan its CSS.** A re-scoped transition block is dead if the deleted module armed its class; nothing here detects it (PR #261).
- **A guard's WIRING**, as opposed to its predicate — groups 9 and 11 both live with this.
- **The screen-reader pass** and the judgement-level a11y items (labels that say what they do, empty state as invitation, colour never the only signal). Axe and Lighthouse are absent; axe belongs in the VR tool light and dark, Lighthouse stays operator-run because it is machine-dependent theatre.
- **Whether a green gate tested anything at all.** The recurring defect shape in this repo: the check skipped the thing it tested. Mutate the source; run the function, don't grep it.
