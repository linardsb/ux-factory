Why does the interviewer say "you don't know yet"?

Full plan: discovery-park-scorer-506.md

What we're building and why

Today we know the interview agent too often files a thin answer as "not known yet", but only as a ratio. After this, a report names every such turn, the agent's own reason, and whether the answer was genuinely ambiguous.

The concepts

Parking

Parking is when the agent records "this person doesn't know yet" instead of judging the answer. Like a teacher marking "absent" for a student who answered badly. This plan counts the wrong parks.

An answer key, sealed in advance

Every test answer was written as one of three kinds: good (K1), thin (K2), or "don't know" (K3). The key was locked before any run. That lets us compare what the agent did with what it should have done.

K1 good      → should record a decision
K2 thin      → should flag it as weak
K3 unknown   → should park it

A blind second opinion

Some thin answers sit on the line between "thin" and "don't know". A separate reader marks those, without seeing what the agent did, so its verdict can't be bent toward the agent's mistakes.

A check that survives re-recording

The next ticket re-runs these interviews, so the exact numbers will change. The automated check (the gate) tests a rule that stays true on any honest run: every park lands in exactly one class.

How the pieces fit

Sealed answer key→ Blind borderline read→ Park view (counts + reasons)→ Gate check→ Report + session read→ Next ticket's prompt fix
