A checkbox-or-radio part

Full plan: choice-primitive-through-the-chain-309.md

What we're building and why

The design system cannot show "tick this box" or "pick one". After this, a part called choice draws a real checkbox or radio, completing the ten basic building blocks.

The concepts this plan rests on

1. Radio buttons share a name

Radios with the same name (an HTML attribute that groups inputs) form one set: picking one un-picks the rest. The browser does this, so the part just copies its group into name.

2. A spec, a style, a template

Each part has a spec (the rules), CSS (the look) and a template (code that builds it). Generators then rebuild the shared files, like reprinting every menu after a recipe changes.

choice.md  →  components.css  →  agentic-renderer.mjs
                      ↓ regenerate
     vocabulary · pack · importer fixtures · screenshots

3. A check needs a control

A test that always passes proves nothing. So each check has a control (a case that must behave differently): radios in different groups must both stay picked.

4. Some facts only a real browser knows

The fast test uses a fake page that only records attributes, so it sees the name, not a click. A second test clicks in three real browser engines.

How the pieces fit

Spec + style + template→ Regenerate shared files→ Fast check: the name is written→ Browser check: clicks behave→ New screenshots
