Catching a look-up typed in the wrong box

Build brief for ticket #454. The full plan: jev-answer-box-guard-454.md

What we're building and why

Today, if you type "look this up" into the answer box, it is saved as your answer and no search happens. After this build, a fast checker notices, and the drawer asks you which you meant.

The concepts this rests on

A yes/no classifier

A small model that reads text and gives a probability instead of writing prose. Here it is Jev, and each yes/no question is a "Noul".

We need one question answered fast: is this a request to look something up?

"Look up WCAG 2.2…" → look_up: 0.93
"We test with VoiceOver" → look_up: 0.04

(illustrative numbers, not real Jev output)

A threshold

The cut-off where a probability becomes "yes". Set it too low and honest answers get flagged. Set it too high and real look-ups slip through.

We pick it by a rule written down before we see the results, so nobody tunes it until it looks good.

Fail-open

If the checker breaks, the door stays open: your answer goes through as it does today.

The check is a helpful question, never a gate. A missing key or a slow reply can't block you.

A labelled test set

Examples where we already know the right answer. Here that is 4 real mistakes from run 1 and 160 real answers.

Running them once and saving the raw replies means the numbers can be re-checked for free, forever.

How the pieces fit

You press Submit→ Portal asks Jev (≤1.5 s)→ Threshold decides→ "Send as a look-up / as my answer?"→ Existing look-up or answer path

Beside it, a separate test run checks the threshold against the labelled set.
