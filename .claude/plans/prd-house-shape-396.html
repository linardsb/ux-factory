PRD house shape — the ladder line

Ticket #396 · full plan: prd-house-shape-396.md

What we're building and why

Every epic in this repo starts as a PRD (a short document saying what problem to solve and why). Nine exist, and they each announce their progress in a different way, or not at all. After this, all nine open with one identical line that says how far the epic has got, and the tools that move an epic forward rewrite that line themselves.

The concepts this rests on

1. The ladder

An epic climbs four rungs: the idea is written, the engineering approach is decided, the work is cut into tickets, the tickets close. The header line records which rung the epic is on. Like a parcel-tracking page: one line, four stages, ticked in order.

**Status:** intent · grilled 2026-08-27 · architecture: decided 2026-08-27 · sliced: #279 2026-08-27 · **Created:** 2026-08-26

The one line, as it will read on the discovery epic. "grilled" means the idea was cross-examined before it was accepted.

2. Whoever moves it, writes it

A status line goes stale the moment nobody owns updating it. One epic here already says "architecture TBD" while its architecture doc has existed for five weeks. The fix is to make the step that changes the state also change the line. A skill (a saved recipe the assistant follows) does each step, so each skill gets one extra instruction.

3. Parked is not refused

A PRD lists things it will not do. Some are refused for good ("no user accounts"); some are only postponed ("the canvas is a later epic"). Mixing them hides the plan for the future. The new §Later, not never holds the postponed ones, so a reader can tell "no" from "not yet".

4. Only facts that already exist

Every date in a new header comes from git history or the GitHub issue, never from memory. Where no record says an idea was grilled, the slot is left out rather than guessed. Writing the owner's decisions for them would make the document lie.
