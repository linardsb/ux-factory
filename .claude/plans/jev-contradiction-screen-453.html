Contradiction screen before the audit

Plan: .claude/plans/jev-contradiction-screen-453.md

What we're building and why

Today the audit agent reads a document one question at a time, so it never notices two places that disagree. After this, a cheap classifier flags suspicious pairs first, and the agent checks them.

The concepts this rests on

Splitting a document into claims

We cut the document into small statements, each with a fixed label like c017. Stable labels let every later step, and every test, point at the same sentence.

## MVP
7. A transition note is required…   → c052
9. One real run: Faster Payment…    → c058

A classifier, not a writer

Jev is a classifier (a model that only picks answers and scores them, never writes prose). It costs about a cent to check every pair. Here it acts like a smoke detector: it flags a pair, Claude checks it during the audit, and the owner rules on it.

Deciding the cut-offs in advance

A threshold (the score a pair needs to be kept) is fixed before the run, without looking at the right answers. Setting it afterwards would mean tuning the test until it passes.

A fingerprint of the prompt

A fingerprint (a short hash of the prompt's text) is saved with every recorded run. If the prompt changes, old recordings stop matching. So the new block appears only when there are pairs, and gets its own fingerprint.
