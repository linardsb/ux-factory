Studio 21 — the epic close (#223)

A five-minute briefing on what this plan builds, and the ideas it rests on.

1 · What we're building and why

Epic #202 shipped twenty tickets: the portfolio's /factory page became a prototype studio. This last ticket ships no feature — it judges the epic. Real strangers use the studio while we watch in silence, the three win-metric signals are verified on the live site, every number and honesty label on the shipped pages is traced back to a generated artifact, and what was cut or deferred is written down. Last epic, this exact ticket (#177) was skipped — the audit never ran. This time it is nobody's option to skip.

2 · The concepts this plan rests on

conceptVirtual-route analytics — the path is the entire payload

Cloudflare Web Analytics has no custom events; it only counts pageviews. So this site encodes an event as a fake, momentary navigation: push /factory/took-over into the address bar, let the beacon's history hook see it, restore the real URL 50 ms later. The path string is the whole message — which is why each is a static literal, fires exactly once, and only from the code path where the thing actually happened (an export that failed to assemble must never count as a keep).

Analogy: a lighthouse flashing a fixed pattern — the pattern is the message, so two meanings must never share one pattern. Where it breaks: a lighthouse repeats; these flash once per visit, deliberately.

Why this plan needs it: the audit's job is to confirm each flash on the live site — and the twist is that the beacon is dark until launch (BEACON_TOKEN = "", fail-closed). So the honest live check watches the history flip itself, with a hook installed before any module loads.

conceptHallway testing — cold readers are a non-renewable resource

3–5 people who have never seen the site, silence for the timed part, verbatim notes, two fixed questions. Small samples find the big confusions (the NN/g result); silence matters because a single hint destroys the one thing being measured — what a stranger does unprompted. And a tester is spent after one session: they can never be cold again, so recruitment is the plan's critical path and starts on day one.

Analogy: taste-testing a recipe — you can't un-tell someone what's in the dish.

Why this plan needs it: the epic's named failure mode — "visitors watch the replay without ever grabbing the wheel" — is invisible to every automated gate. Only a cold human can produce it. Round 3 adds a studio part to the existing (never-run) v3 script: name the page, never the capability, and log whether they grab the wheel unprompted.

conceptNumbers as claims — every stated figure has a generated source

This repo's honesty contract treats every on-page number (component count, control count, line counts) as a claim that must trace to a machine-measured artifact — loc-summary.json, param-count.json, the fetched pack. A hand-written number can silently rot; a generated one is drift-checked in CI. The audit re-runs every generator (tree must come back unchanged), sweeps all eleven pages for digits, and records a verdict per number — "checked, not assumed" means the triage table exists, not that someone looked.

Why this plan needs it: twenty tickets of copy churn is exactly how a true number goes stale, and the catalog just doubled to twenty components.

conceptThe epic close as a ticket — audits that are nobody's job don't run

A process step with no owner and no artifact evaporates under delivery pressure (#177, closed NOT_PLANNED). Making the close a ticket gives it acceptance criteria, a PR, and a paper trail: cuts recorded on the epic issue, dated closing notes in the PRD settling each success-metric row honestly — including the two rows that cannot be judged before launch (keep/share and take-over rates need the beacon live; the note says the clock hasn't started rather than pretending a verdict).
