Import suggestions

Full plan: jev-import-suggestions-455.md

What we're building and why

When the importer can't name a design part, the owner scans all 26 components by hand. After this build, a fast classifier ranks the three likeliest components beside that part, and the owner picks.

The concepts

1. Decide, narrow, ratify

A rule-based matcher (fixed code rules) decides what each part is. A classifier only suggests. A person confirms. The suggestion lives in its own field, so it can never change the decision.

matcher:   "not sure"          ← still the answer
Jev:       stack 0.62, list-row 0.21, none 0.08
owner:     clicks "Use stack"  ← the owner's edit

2. A Choice question

Jev (a small, fast AI classifier) picks one option from a list and gives each option a probability (a likelihood from 0 to 1). We ask one question per unnamed part, with every component plus "none" as options.

3. Fail open

Fail open means: if the helper breaks, carry on as if it wasn't there. No key, a timeout or an error gives an empty list, and the import still finishes. Like a satnav losing signal: you still arrive.

4. A recorded real answer

We call Jev once for real and save the exact request and reply in the repo. The automatic checks replay that saved reply, so they never spend money or invent an answer.
