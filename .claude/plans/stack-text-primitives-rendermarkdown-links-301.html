A box, and some words

Build brief for the two new parts of the design system.

Full plan, with every trap and number: stack-text-primitives-rendermarkdown-links-301.md

What we're building, and why

The design system has 21 components and no way to arrange them, so every composed screen is a flat list.

After this there are two more parts: a box that holds any number of things in a row or a column, and a text part whose size comes from a single word.

The four ideas it rests on

1 · The renderer only knows what it's told

It builds components from a fixed list and refuses everything else before a pixel is drawn. That list is the vocabulary (a generated file naming every component and its rules). Like a vending machine — it dispenses only what is loaded. The new parts must be added to it, or they cannot be used.

2 · How many children, not which

Most parts hold at most one thing inside them. A box needs to hold many, so the system has one word for that: cardinality (how many children are allowed). A separate list still says which are allowed. Like a shelf — the label says “books”, the length says how many fit.

3 · The box never writes its own spacing

It writes a label — data-gap="md" — and the stylesheet turns that label into the system's medium spacing value. Like a coat-check ticket: the box carries the number, the cloakroom holds the coat. Every measurement stays in one place, so re-skinning the site still moves it.

4 · One text renderer, shared

The system already turns simple markup (bold, code, bullet lists) into real page elements, in one file two pages use. The new text part uses that same file rather than a copy, so adding links there gives every surface links at once. One kitchen, three dining rooms.
