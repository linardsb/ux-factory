Look it up, park it, say something else

Build brief for ticket #289. The full plan — every task, gate case, trap and open question — is discovery-affordances-289.md.

What we are building and why

Today a discovery session has one move: answer the question on the screen. You cannot check a fact, skip one you honestly cannot answer, or say anything the question did not ask. After this there are three more buttons, and the record refuses to move on until each has left its mark.

The ideas this rests on

1. A turn either closes or attaches

A turn is one question and everything around it. Some things the agent files end the turn; others attach and leave the question standing. The new moves attach — except parking, which ends it on purpose.

question 7 on the screen
  ├─ look it up   → attaches, question still standing
  ├─ say something else → attaches, question still standing
  └─ your answer  → CLOSES → question 8

Only one arrow moves you forward — and it is blocked while an aside above it is unrecorded.

2. Four words the agent is allowed to say

The agent can only file four kinds of record: a decision, a weak-answer note, an open question, and a piece of evidence. All three new moves reuse those four. Nothing new is added to the vocabulary — the moves are new, the words are not.

look it up  → evidence (a link, labelled "secondary-source")
park it     → open question ("banked", plus your reason)
say else    → decision (you chose) or open question (you didn't)

3. A frozen prompt is a receipt

Every past session records a fingerprint — a short code for the instructions the agent was given. Change one character and seven recorded sessions stop matching. So the new text goes in the per-question message, not the standing one.

Two are 65 questions long; re-recording them destroys a sealed experiment. The two stances nothing was recorded under are free to change, and one rule changes them.

4. Refusing is how the record stays true

The record-keeper never writes anything itself. When a move breaks a rule it says no, and the agent reads the refusal and tries again in its own words. That is how a rule can be strict without putting words in anyone's mouth.

It blocks moving on to the next question. It never blocks finishing — a session can always be ended.

How the pieces fit

     you press a button
             │
      ┌──────┴──────┐
   the server    stores what you typed, word for word
      │
   the agent    given the standing instructions + one extra paragraph
      │
   it files     one of the four records
      │
   the package  three files on disk — the only state there is
      │
   the screen   reads the package back and says what was filed

The extra paragraph is where the three affordances live, and it never reaches a normal question.

The plan at a glance

  1. Phase 1 — an aside must not replace your answer, must not end a question, and must not be left unrecorded. Independent of the rest.
  2. Phase 2 — the four new instruction paragraphs, and proof the old ones did not move.
  3. Phase 3 — the server learns the two new kinds of turn needs Phase 2
  4. Phase 4 — three buttons in the workbench needs Phase 3
  5. Phase 5 — the checks needs 1–4
  6. Phase 6 — docs, then the full check run
  7. Phase 7 — one paid run to see whether search actually works

Done means

1Looking something up files links, and does not end the question.
2Parking files your reason, moves on, and shows up in the "not a form" count.
3Saying something else always files one of two things — and the question will not close until it has.
4Neither ends a question, and neither moves you forward.
5Search is allowed by name, never by file path.
6Any record with nothing above it is flagged, and the chain can be walked to the top.
+An exchange left unrecorded at the very end is named in the finished document, never hidden.
