A part that can't be built should say so, not crash

Source of truth: stack-refused-without-layout-477.md

What we're building and why

Today the owner can tell the importer "treat this box as a stack". If the box never said which way its items run, the importer builds a broken part anyway, and the preview crashes. After the fix, the part is not built, and the screen explains why.

The concepts this plan rests on

1. Required props (the settings a part can't do without)

Every part in the design system lists settings it must have. A stack must know its direction: row or column. The fix hinges on this list.

stack   → direction (required), gap, pad, align
icon    → name (required), size (required)

2. "Present" is not "filled"

The builder checked that the slot for direction existed. It never checked that anything was in it. Like a form with the "date" box printed but left blank. The fix checks the value, not the box.

before: is there a direction key?     yes → build
after:  does direction hold a value?  no  → don't build

3. A loss list (the record of what couldn't be carried over)

When the importer can't use something, it writes a row saying what and why. Skipping a part is honest when the row exists. If a refused part had already built smaller parts inside it, each of those gets a row too, so nothing disappears unnamed.

4. A check that must be able to fail

The new check tries every part of two saved designs against every builder: 144 pairs. On today's code 16 of them crash, so the check goes red. It also confirms a real stack still builds, so it can't pass by refusing everything. A second check runs the owner's real mapping step end to end.

How the pieces fit

Owner maps a box to "stack"→ Builder fills settings→ Direction empty? Don't build, log why, name what went with it→ Screen: "not emitted, see drops"

Before the fix, step three let the empty value through, and the preview crashed with "Refused by the renderer".

The plan at a glance

  • Phase 1, the checks: the 144-pair sweep and the end-to-end mapping check. Written first, so you watch them fail.
  • Phase 2, the rule: check values, not keys, and log every part a refusal takes with it. Needs Phase 1 in place.
  • Phase 3, the wording: update the gate descriptions, then run everything.
