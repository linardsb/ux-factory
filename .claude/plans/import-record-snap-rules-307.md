## Feature Description

Two pieces of the design-import core (`import/`), both Node-only and both driven by build-checks in CI:

1. **The import record.** `imports/<id>.json` is the artefact an import leaves behind: what was read, how
   it mapped, everything that was lost (in E1's three drop classes), and a fidelity block that says
   whether the result *looks* like the source. `imports/<id>.md` is a pure fold of that JSON for
   engineers. The record is built so that it **cannot lie**: the drop list, the unbound counts and the
   fidelity verdict are *derived* and a validator refuses any record whose stored copy disagrees; an empty
   measurement reads `missing`, never `green`.
2. **The snap step.** A source drawn without design-system tokens ("unbound": raw `12px`, raw `#0c3b2f`)
   gets each raw value matched to the nearest contract token, per family, with the distance recorded.
   Exact matches resolve silently, near matches become visible proposals, misses drop. An owner's fixes
   for one source file are remembered by the file's hash and reused on re-import.

The fidelity number comes from S3's detector (#300): **rung 6, ink-colour ΔE (CIEDE2000)** per part,
lifted into `import/fidelity.mjs`.

## User Story

As the owner running an import in the portal
I want every import to leave a record that states what mapped, what was lost, and whether the result looks
right — and to snap raw values to my tokens where the match is honest
So that a stakeholder can audit the import, and a formally green but visibly wrong import (spike A's green
body text, 12/12 WCAG) is reported red instead of shipped.

## Problem Statement

Spike A shipped a Polaris mapping that passed 12/12 WCAG with dark-green body text, and 52 of 238 tokens
appeared nowhere in its report. Nothing in `import/` today records what an import lost or measured, and an
unbound value is either dropped by the converter (`import/brilliant.mjs:291-293`, reason text "by-value
snapping is #307's") or carried with `ref: null` that nothing fills.

## Solution Statement

- `import/fidelity.mjs` — S3's rung-6 detector lifted from `.claude/plans/canvas-spike-s3/compare.txt`
  (PNG decode, CIEDE2000, per-region modal/ink, the MIN_AREA/DEGENERATE exclusions), cut to one rung, with
  one stated fix (ink-missing fallback). Absolute threshold **5.0**, results rounded to 4 dp.
- `import/snap-rules.mjs` — families, tolerances, the pure `snap(ir, targets, overrides)`, source hashing
  and the override file loader. O3a's three outcomes are the rule.
- `import/report.mjs` — `buildRecord`, `checkRecord`, `fidelityVerdict`, `checkReferenceIndependence`
  (O3b), `projectRecord` (the markdown fold).
- A converter change so unbound spacing reaches the snap step, and a `stackShape` guard so an unsnapped
  gap is a recorded drop rather than `gap: null`.
- Frozen fixtures under `import/fixtures/`, two committed fixture records generated by
  `tooling/regen-import-records.mjs`, and build-checks **group 42** "import-record".

### Patterns to Follow

**Pure modules take data, not paths.** `recognise(ir, vocab)` takes the vocabulary as an argument (`recognise.mjs` header: "THE VOCABULARY IS AN ARGUMENT"). **Errors** name the path: `throw new Error(\`record.drops: …\`)` (CLAUDE.md § Ground rules; `checkIr`'s style).

## DECISIONS THIS PLAN MAKES (reversible; each flagged in Open Questions where the owner may differ)

- **D1 — rung 6, not rung 2.** S3's pre-committed predicate named rung 2 (first rung to fire). A live
  record has no faithful floor render, so the 2x-floor margin cannot be applied; only an absolute threshold
  above every engine's floor works. Rung 2's worst floor (WebKit **5.1005**) is above rung 2's own 2.3
  threshold, so rung 2 would read a faithful WebKit render red. Rung 6's worst floor is **2.6888**, under its
  **5.0** threshold (1.86x). Rung 6 is also independent of the 256 px region rule. → Q1.
- **D2 — ink-missing fallback.** S3's `regionStats` returns `inkColourDeltaE = 0` when either side has no
  ink. A candidate that drops a text entirely therefore scores 0 (green). The lift compares
  `inkA.mean ?? modA.rgb` against `inkB.mean ?? modB.rgb` (no ink ⇒ the region's paper colour). Observed:
  a blanked `subtitle` scores **0 → 25.2780**; every committed fixture number is unchanged to 4 dp.
- **D3 — verdicts are `red | green | missing`.** No `unmeasured` (S3 took the red leg).
  `missing` ⇐ fidelity absent/`{}`, `deltaEMin` null, zero scored regions, `wcag` absent, or `wcag.total === 0`.
  `red` ⇐ `deltaEMin.value >= 5.0` or `wcag.pass < wcag.total`. Otherwise `green`.
  **wrong-but-green** ⇐ `wcag.pass === wcag.total && deltaEMin.value >= 5.0`.
- **D4 — snap outcomes (O3a).** Per unbound slot: `exact` (distance 0 to exactly ONE token) → `ref` filled
  silently; `proposed` (inside tolerance, or a distance-0 tie across several tokens) → `ref` stays null, row
  lists the candidates; `dropped` (outside tolerance, or no family) → `ref` null + a `no-snap-target` drop
  row on the node; `override` → the owner's ref is written. Bound slots (`ref !== null`) are never touched —
  mapping is by role for those (`brilliant.mjs` contract 2).
  **Ties:** `candidates` lists every target at the minimum |distance|, each with its OWN signed distance.
  The row's `distance` is the shared minimum |distance| as a number when every candidate has the same
  signed distance, and `null` when the tied candidates straddle the value (Card gap 12: `--spacing-sm` −4,
  `--spacing-md` +4). A `null` distance renders "tie — see candidates".
- **D5 — families and tolerances** (architecture: "snap tolerances … decided at implementation"):

  | family | slots | targets | tolerance | distance |
  |---|---|---|---|---|
  | spacing | `layout.gap`, `layout.pad[0..3]` | `brilliant.mjs` `SPACING` (4,8,16,24,32,48,64,96) | 2 px (half the smallest step) | contract − source |
  | type | `text.size` | `recognise.mjs` `TYPE_ROLE_PX` → `--type-display/h2/body/caption` (40/24/16/13) | 1 px | contract − source |
  | radius | `style.radius` | contract `radius` group (4,8,16) | 2 px | contract − source |
  | colour | `style.fill`, `style.stroke.color` | contract `fg-surface`/`accent`/`inverse` hex tokens (16; `color-mix` skipped) | ΔE2000 ≤ 2.3 (JND) | ΔE, unsigned |
  | none | `text.lineHeight`, `style.stroke.width` | — | — | dropped, reason "the contract has no <x> family" |

  Type uses TYPE_ROLE_PX, not the eight-step ramp, so the snap and `recognise`'s role fill give one answer
  for one value (12px → caption, not eyebrow). → Q3.
- **D6 — overrides** are keyed by the full sha256 hex of the source file's bytes; the file lives at
  `<dir>/<hash>.json`. Rows are keyed `path` + `slot` (same hash ⇒ identical tree ⇒ identical paths). An
  override naming a slot with no snap row, or a ref outside the slot's family, is refused by name. The
  fixture override lives in `import/fixtures/overrides/`, not `import/overrides/`, because an override is
  the owner's decision and a gate fixture is not one (memory: honesty contract runs both ways). → Q4.
- **D7 — snap rows live on the node** (`node.snaps`, beside `node.drops`), added only to nodes that have
  one; `ir.mjs`'s `node()` is not changed. `snap` returns a new tree and never mutates its input.
- **D9 — the markdown uses only what `renderMarkdown` renders faithfully** (`system/handoff-viewer.mjs:202-260`, read 2026-09-23):
  no `#` headings (none exist — a section opens with a **bold line**); **no nested lists** (the list branch
  `trimStart()`s every item, so indentation is lost); pipe tables only for fields that carry no free text,
  because `splitRow` (`:189-194`) splits on every `|` with no escape and drop reasons contain `{fill | hug}`
  and `a | b` lists. Free text (drop reasons, notes) goes in bullets. Every table cell passes through one
  `cell(v)` helper that replaces `|` with `/` (a designer's layer name can hold one); the JSON keeps the
  original. 42.6 renders both committed mds through the real `renderMarkdown` to prove it.
- **D8 — the record carries `unbound {slots, exact, proposed, dropped, overridden}`**, derived. The
  ticket's "count of unbound imports" is then a fold over records (`source.bound === false`). → Q5.
