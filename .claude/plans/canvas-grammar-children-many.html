One container, many parts

Build brief · ticket #298 · full plan: canvas-grammar-children-many.md

What we're building

Today a container in this design system can hold one thing inside it, and only one. After this change a container can declare that it holds many — which is what the next tickets need before they can build a box that stacks several parts.

The ideas this rests on

The vocabulary

A generated list of every component an AI agent is allowed to use, and the settings each one takes. A checker reads that list and refuses anything not on it.

Like a restaurant menu: you may order anything printed on it, and nothing else. This change edits one rule on the menu.

Cardinality

Cardinality means "how many". The menu already says which components may sit inside a container. It has never said how many. We add one word for the containers that need it.

"children": ["metric-tile"],       which may go inside
"childrenCardinality": "many"     how many may go inside

Say nothing and you get the old answer: at most one.

Generated files are committed

Several files here are written by scripts rather than by hand, and the live site serves the repository exactly as it is. So those outputs are committed like source.

A gate re-runs every script and compares. If the committed copy differs, the build goes red — so editing a script means regenerating in the same change.
