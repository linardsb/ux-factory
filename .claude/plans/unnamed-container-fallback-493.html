Unnamed containers lose to the fallback

Full plan: unnamed-container-fallback-493.md

What we're building and why

Today, admitting a new "holds many things" component makes the importer mislabel plain boxes, and three checks fail. After this fix, such a component only wins a box when the designer actually named the box after it.

The concepts this rests on

A matcher that scores evidence

The importer guesses what each drawn box is by adding up clues: the box's name, its shape, what text it holds. A total of 0.5 or more wins. This build changes which totals may win.

name matches   +0.45
shape fits     +0.25
text fills it  +0.25
--------------------
win if ≥ 0.50

The fallback ("stack")

When nothing wins, a laid-out box is called a stack, a plain "box of things". It is honest: "we know it's a box, not what kind". This build makes more boxes reach it.

Free evidence

Some clues fire on almost everything. Like a detective counting "the suspect has hands" as evidence. A container component gets "shape fits" from every laid-out box and "text fills it" from any box with words. That free 0.5 is the bug.

A name is real evidence

The fix: a container wins only if the box's name matches it. "Top bar" can still be a top bar. An anonymous "Text block" stays a stack.

How the pieces fit

Drawn box→ Score every component→ Skip unnamed containers→ Best ≥ 0.5 wins→ Else: stack
