## Summary

/build's ten method questions now have a second, build-time job. Three committed rules in a new
`portal/lib/builder.mjs` draft the **question a real Agent SDK run answers** about a scenario's own
fixtures — `shape` names the question, `action` names who it is for, and the other eight enter no
prompt — and a portal drawer renders the shipped question config, previews the draft against the
scenario's own slot bounds and ethics verdict, and streams the run's PIV phases live. One real run
was driven from that drawer against `northwind`; its composition, trace pair and manifest upsert are
committed, and `/instance.html` renders it in the prototype slot with **no code change** downstream.

The runner's honesty machinery is untouched. `buildTask`, `PIV_COMPOSE_SYSTEM`, `refsFor`,
`makeFence`, `SECRET_PATHS` and the CLI's argv parser are byte-identical to `origin/main` (proven
mechanically, below). The ten answers reach the agent only as the question *text*, which is what
keeps `record-composition.mjs`'s load-bearing header claim true.

## Deviations from the plan

1. **`builder.mjs` imports `record-composition.mjs` statically; the SDK import inside
   `record-composition.mjs` became lazy instead.** The plan required the import of
   `record-composition.mjs` to be *dynamic, inside `runBuild`* so the SDK stays out of the gate's
   graph — but it also required `readScenario` to get `compose.json` from the now-exported
   `loadComposeConfig`, and `readScenario` is synchronous and called by `listScenarios`/`draftRun`.
   Those cannot both hold: a static import drags in the SDK, and a dynamic one would make AC12
   ("every guard reachable by the gate without the Agent SDK") and AC3's run-path assertion
   unachievable — in CI, `runBuild('verdant')` would fail with `Cannot find package
   '@anthropic-ai/claude-agent-sdk'` rather than the boundary message. `lib/trace-recorder.mjs` is
   the *only* SDK path in that file's graph, so it is now loaded with
   `await import(...)` inside `runComposition`, after every guard. The invariant becomes one
   sentence — **the SDK loads only when a run actually starts** — and it is proven, not asserted:
   with `portal/node_modules` moved away, group 8 passes and the verdant refusal names
   `compose.json`. Keeping a redundant dynamic import in `runBuild` on top of the static one would
   have been dead weight that lied about how the module loads, so it was dropped.
2. **CLI guard uses `process.exitCode = 1`, not `process.exit(1)`.** `summarize()` has just
   `console.log`'d and on a pipe that write is still queued; `process.exit()` would drop it, making
   AC6's "printed output unchanged" false. Verified: no args → `exit=1`, message intact.
3. **The `--dry` branch also returns the structured outcome.** The plan's refactor task addressed
   mainly the real path, but `record-composition.mjs:351` and `summarize()` both wrote
   `process.exitCode` on the dry path too. `ok = valid && clean` reproduces the old exit condition
   exactly; without this the CLI's dry-run exit code would have silently changed.
4. **Group 8's `fictional: false` run-path check uses `verdant` (no `compose.json`).** No
   `fictional: false` package exists in this repo and writing one would be a fake artifact. So
   `assertFictional` is called directly with in-memory heads (`false`, key missing, null) for the
   privacy message, and the *structural* claim — a guard fires on the run path before the SDK is
   reached — is proven with the other refusal `readScenario` raises. The discriminator is the
   message text, and that is stated in the group's comment.
5. **Two group-8 assertions were restructured to report instead of crash.** The first versions let
   an uncovered `shape` option throw out of `draftQuestion`, and an unreleased lock reject out of a
   bare `await` — in both cases the gate died with a stack trace *before* `group()` printed the
   failure it had already recorded. Both now fail cleanly and name the broken invariant. (Found by
   the mutation battery: two mutations went red "messily" and would have read as ambiguous.)
6. **`portal.css` gains a page-scoped `[hidden] { display: none !important; }`.** `.btn` is
   `display: inline-flex`, so `#builder-run.hidden = true` was a no-op — the same bug the file
   already carries two scoped one-off fixes for. Verified in the browser: `display: "none"`.
7. **`ACTS` is served from `/api/build/config`.** The drawer labels the two acts; the alternative
   was hardcoding "Act 1 · Hooked", which is the fork AC1 forbids.
8. **A seventh mutation was added** to the Level-2 battery (`validateAnswers` ignoring unknown
   keys), since that guard's own bite was otherwise unproven.
9. **`server.mjs`'s header line was corrected** — it claimed the SDK powers `/api/chat` only, which
   `/api/build/run` made false.
