## Summary

The route's contradiction screen is now one Claude call (`claude-opus-5`) over the whole document. The call returns
pairs of verbatim quotes, which a pure mapper turns into claim ids through the document's source lines. Only pairs
with both quotes on one claim each reach the unchanged `tensionsBlock`. The screen stays off. It was
pre-registered, then run once on a synthetic smoke document, once on the frozen fixture and once on the live PRD.
All three runs are committed and replayed in build-checks group 45. **The fixture scored 1 / 3 contradiction-class
findings (#2 FOUND)**, against Jev's 0 / 3.

## Issues encountered

- **The harness bills two helper models on every query**: `claude-sonnet-4-5-20250929` (about $0.014 per run) and
  `claude-haiku-4-5-20251001` ($0.003–0.014), alongside `claude-opus-5`. Their token counts do not match the
  call's `usage`, which is Opus's alone. Reported per the rubric and not scored. What those helper calls carry is
  not visible from the SDK's result, so invariant 1 is asserted for the answering call's options, not for the
  harness's own background calls.
- **`claude-summary.inputTokens` reads 2 on the fixture run** because the SDK reports the prompt as
  `cache_creation_input_tokens` (8,922). The line shape was fixed before the run and replayed byte for byte, so the
  number is documented in the README rather than changed.
- **The live run dropped 3 of 6 returned pairs as `same-claim`.** Two have both quotes inside c001, which the
  splitter makes from the live PRD's lines 3–16 as one claim. This follows the pre-registered rule, and it affects
  the live check only, which is unscored.
- The mutation driver's first pass was a false NOT RED (it read stdout only). It was caught because every mutation
  read the same way, and it was fixed before any result was trusted.
